<objective>
Build the deterministic foundation for Phase 2 — Pydantic extraction schemas, crop/unit normalization, and the conversation state machine with conflict-aware merge policy.

Purpose: These three modules are the trust foundation. If normalization is wrong, every downstream eligibility result is wrong. If state merge is wrong, farmers get re-asked for answered slots or lose confirmed values. All of this is pure Python — no LLM, no API key.

Output: `backend/nlu/schemas.py`, `backend/nlu/normalize.py`, `backend/conversation/state.py`, and a comprehensive test suite.
</objective>

  <files>backend/nlu/normalize.py</files>
  <action>
    Create `backend/nlu/normalize.py` with:

    1. `CROP_CANONICAL_MAP: dict[str, str]` — lowercase lookup mapping local Kannada crop names to canonical English names used by the rules engine:
       - "togari" / "ತೊಗರಿ" → "Pigeon Pea (Togari)"
       - "jola" / "ಜೋಳ" → "Jowar"  (note: rules_engine uses "Jowar" not "Sorghum")
       - "ragi" / "ರಾಗಿ" → "Ragi"
       - "kabbu" / "ಕಬ್ಬು" → "Sugarcane"
       - "paddy" / "ಭತ್ತ" → "Paddy"
       - "cotton" / "ಹತ್ತಿ" → "Cotton"
       - "groundnut" / "ಕಡಲೆಕಾಯಿ" → "Groundnut"
       - "maize" / "ಮೆಕ್ಕೆ ಜೋಳ" → "Maize"
       - "pigeon pea" → "Pigeon Pea (Togari)"
       - "sorghum" / "jowar" → "Jowar"
       - "finger millet" → "Ragi"
       - "sugarcane" → "Sugarcane"
       Check `data/schemes_dataset.json` for EXACT crop names used by the engine and ensure the mapping targets match.

    2. `normalize_land_size(land_size: LandSize) -> float`:
       - If unit == "gunta": return value * 0.025
       - If unit == "hectare": return value * 2.471
       - If unit == "acre": return value
       - NEVER round. Return exact float.

    3. `canonicalize_crop(local_name: str) -> str`:
       - Lowercase lookup in CROP_CANONICAL_MAP
       - If no match, return the original name (do not guess)

    4. `canonicalize_crops(crops_local: list[str]) -> list[str]`:
       - Apply canonicalize_crop to each, deduplicate, preserve order

    5. `is_land_size_sane(acres: float) -> bool`:
       - Returns True if 0.01 <= acres <= 100.0 (guardrail from AI-SPEC §6)

    6. `IRRIGATION_TO_WATER_SOURCE: dict[str, bool]` mapping:
       - "Rainfed" → False, "None" → False
       - "Borewell" → True, "Canal" → True, "Open Well" → True

    7. `extraction_to_farmer_profile_fields(extract: ExtractOut) -> dict`:
       - Converts an ExtractOut into a dict of FarmerProfile-compatible fields
       - Normalizes land_size → land_acres
       - Canonicalizes crops_local → crops
       - Maps irrigation_source → irrigation_type + has_water_source
       - Maps ownership_type → ownership
       - Does NOT fill fields not in ExtractOut (season, risk_type, equipment, soil health, exclusions) — those come from follow-up dialogue

    AVOID: Importing or calling any LLM — this module is pure Python math + lookups.
    AVOID: Rounding acre values — 20 guntas must be exactly 0.5 acres, not 0.50000000001.
    AVOID: Hardcoding crop names that don't match the rules_engine — read the actual values from test_rules.py and schemes_dataset.json.
  </action>

<task type="auto">
  <name>Build conversation state with conflict-aware merge + tests</name>
  <files>backend/conversation/__init__.py, backend/conversation/state.py, backend/tests/__init__.py, backend/tests/test_conversation_state.py</files>
  <action>
    Create `backend/conversation/__init__.py` and `backend/tests/__init__.py` (empty).

    Create `backend/conversation/state.py` with:

    1. `ConversationState(BaseModel)`:
       - `session_id: str`
       - `confirmed_profile: dict` — flat dict of confirmed FarmerProfile fields (e.g., {"land_acres": 3.0, "irrigation_type": "Borewell"})
       - `inferred_slots: dict` — low-confidence values needing confirmation
       - `quarantined_conflicts: list[dict]` — list of {field, old_value, new_value, turn} for conflicting scalars
       - `turn_history: list[dict]` — last 6 turns [{role, content}]
       - `turn_count: int = 0`
       - `schema_version: str = "1.0"`
       - Model config: validate JSON-serializable

    2. `REQUIRED_SLOTS = ["land_acres", "crops", "irrigation_type", "district"]` — the 4 mandatory fields

    3. `merge_extraction(state: ConversationState, new_fields: dict) -> ConversationState`:
       - For each field in new_fields:
         - If value is None: skip (never overwrite with None)
         - If field is "crops": set union with existing crops list
         - If field is a scalar and confirmed_profile has a DIFFERENT value: quarantine the conflict, do NOT overwrite
         - If field is a scalar and confirmed_profile has no value or same value: update confirmed_profile
       - Return updated state

    4. `get_missing_slots(state: ConversationState) -> list[str]`:
       - Returns REQUIRED_SLOTS that are missing or empty in confirmed_profile
       - "crops" is missing if the list is empty
       - "land_acres" is missing if not in confirmed_profile or is None

    5. `is_profile_complete(state: ConversationState) -> bool`:
       - Returns `len(get_missing_slots(state)) == 0`

    6. `add_turn(state: ConversationState, role: str, content: str) -> ConversationState`:
       - Appends to turn_history, trims to last 6

    Create `backend/tests/test_conversation_state.py` with ≥15 test cases:
    - None never overwrites confirmed value
    - Crops are set union (["Ragi"] + ["Paddy"] = ["Ragi", "Paddy"])
    - Conflicting scalar is quarantined (land_acres 3.0 vs 2.0)
    - Same scalar is accepted (land_acres 3.0 → 3.0)
    - Missing slots detected correctly (all 4 required)
    - Profile complete when all 4 present
    - Turn history trims to 6
    - Empty extraction doesn't corrupt state
    - Multiple merges accumulate correctly
    - Quarantined conflict records old and new values
    - JSON serialization roundtrip works

    AVOID: Using `None` as a sentinel for "explicitly empty" — use the absence of the key in confirmed_profile.
    AVOID: Mutating the state in-place — return a new/updated state (or use model_copy).
    AVOID: Adding LLM calls — this is pure Python state management.
  </action>
